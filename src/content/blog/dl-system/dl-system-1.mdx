## 什么是AI编译器？

AI编译器把模型中的计算转换为适合目标硬件执行的形式。除了生成代码，还要处理计算图、算子融合、数据布局和内存使用。

可以先按三个层次理解：

- **图级优化**：看算子之间的关系，比如合并连续的操作、消除无用计算。
- **算子级优化**：决定一个算子怎样执行，比如矩阵分块、向量化和线程划分。
- **硬件映射**：生成目标设备的代码，或调用已有的高效算子库。

## 为什么算子融合能加速？

```python
y = torch.relu(x * scale + bias)
```

在 eager 模式下，乘法、加法、ReLU 可能分别执行，并产生中间张量。融合后，中间结果可以尽量留在寄存器里，减少内存读写和 kernel 启动。

<Note type="hint" title="算子融合">
融合不一定减少数学运算量，主要减少的是执行过程中的额外开销。收益取决于原来的瓶颈，也不是融合越多越好。
</Note>

## 用 torch.compile 理解编译过程

PyTorch 常见的 Inductor 编译路径可以记成：

```text
Python 模型
  → TorchDynamo：捕获计算图
  → AOTAutograd：处理自动求导
  → TorchInductor：优化并生成代码 / 选择算子实现
  → 硬件执行
```

这里是简化后的链路，训练、推理和不同后端的具体路径会有区别。

```python
compiled_model = torch.compile(model)
y = compiled_model(x)
```

第一次调用可能触发编译，因此不能只跑一次就比较速度。输入形状变化还可能引起重编译；遇到无法捕获的操作，则可能出现 graph break，把图拆成多段。

目前先记住：**捕获到计算图不等于一定加速**。需要看减少了什么开销，以及编译成本能不能被后续运行摊薄。

参考：[PyTorch 编译器说明](https://docs.pytorch.org/docs/main/user_guide/torch_compiler/torch.compiler.html)。
